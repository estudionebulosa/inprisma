# 07 — CMS (Sveltia)

The content is managed through **Sveltia CMS**, a Decap-compatible editor whose
form is generated from the same field contract as the JSON Schema and the CI
gates. Non-developers edit and publish articles through a browser form without
touching Markdown files.

## Files

| File | Source | Committed |
|---|---|---|
| `admin/index.html` | CMS shell (loads Sveltia from a CDN) | ✅ |
| `admin/config.yml` | generated by `npm run generate` | ❌ (git-ignored) |

Both are copied to `_site/admin/` by the Eleventy passthrough, so the CMS lives
at `/admin/` on the deployed site.

## Backend

The config uses the **GitHub** backend (`repo` derived from `package.json`), with
the editorial workflow enabled (`publish_mode: editorial_workflow`). Every save
opens a pull request; nothing reaches `main` until it is published.

> Sveltia CMS does not support the deprecated Git Gateway backend. If you migrate
> to Decap/Netlify CMS with Git Gateway, see the fallback at the end of this page.

## Editorial workflow

| Status | Meaning | Git effect |
|---|---|---|
| **Draft** | work in progress | draft PR on `cms/articles/<slug>` |
| **In Review** | ready for review | PR marked ready |
| **Ready** | approved | PR ready to merge |
| **Publish** | go live | PR merged, branch deleted |

The CI gates run on every pull request. A draft with missing required fields
fails CI (fail-closed) — that is the signal to complete the entry before
publishing. Production stays unaffected until the PR is merged.

## Running locally

Sveltia CMS has a built-in local workflow that needs **no proxy server** and no
OAuth:

1. `npm install && npm run generate && npm run build`
2. Serve the built site and open `http://localhost:4173/admin/index.html`
   (`npm run serve:site`).
3. Click **“Work with Local Repository”** and select the project root.
4. Edit content; changes write straight to local files. Commit and push with
   Git as usual.

## Production (OAuth)

To publish from the CMS on a deployed site, the GitHub backend needs an OAuth
client. Deploy the official **Sveltia CMS Authenticator** on Cloudflare Workers
(see the [Sveltia CMS GitHub backend guide](https://sveltiacms.app/en/docs/backends/github)),
then add its URL to the backend config:

```yaml
backend:
  name: github
  repo: estudionebulosa/inprisma
  base_url: https://your-authenticator.example.workers.dev
```

The `base_url` line is the only deployment-specific change; regenerate the config
or edit `admin/config.yml` accordingly.

## Author onboarding

To add or edit an article as a non-developer:

1. Open `/admin/` and sign in with GitHub.
2. Under **Artículos**, create a new entry or edit an existing one.
3. Fill the form. Required fields (title, excerpt 120–160 chars, hero image +
   alt, 3–5 internal links, revision, date) are enforced before an entry can
   leave Draft.
4. Set `slug` explicitly — the URL derives from it, and internal links depend on
   it being stable.
5. Save → **Send for Review** → a reviewer moves it to **Ready** → **Publish**.

The syndicated copies (Medium, LinkedIn, Substack) and the canonical page are all
produced from the same entry; they carry the canonical/attribution block
automatically.

## Decap CMS fallback

The generated `config.yml` is largely Decap-compatible. To switch:

1. In `admin/index.html`, replace the Sveltia script with Decap:
   ```html
   <script src="https://unpkg.com/decap-cms@^3.0.0/dist/decap-cms.js"></script>
   ```
2. If you deploy on Netlify with Git Gateway, change the backend:
   ```yaml
   backend:
     name: git-gateway
     branch: main
   ```
   and enable local editing with `local_backend: true` plus `npx decap-server`.

Note: Sveltia ignores `local_backend` (it has its own local workflow); Decap
ignores `squash_merges`. The `publish_mode: editorial_workflow` key is honoured
by both.
